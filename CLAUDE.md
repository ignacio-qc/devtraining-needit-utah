# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A **ServiceNow scoped application** ("NeedIt", scope `x_58872_needit`, app sys_id `6ead8e780f603200cd674f8ce1050ed1`) exported via ServiceNow Source Control. It is the ServiceNow Developer Program training app (Utah release), and commits correspond to lab solutions (Flow Designer, notifications, application properties, etc.).

There is no local build, lint, or test tooling. Code runs only inside a ServiceNow instance; changes are normally made in Studio / the instance and committed from there.

## Structure

- `sys_app_<sys_id>.xml` — application record.
- `update/` — one XML file per application record, named `<table>_<sys_id>.xml` (or `<table>_<name>.xml` for dictionary/documentation records). Each file is a `<record_update table="...">` wrapper around the record's fields. Script bodies (business rules `sys_script`, client scripts `sys_script_client`, script includes `sys_script_include`, email scripts, scheduled jobs `sysauto_script`, transform scripts, flows `sys_hub_flow`) live in `<script><![CDATA[...]]></script>` fields.
- `dictionary/` — table schema per table: `x_58872_needit_needit` (main request table), `x_58872_needit_needit_task`, `x_58872_needit_historic_` (import target).
- `author_elective_update/` — choice lists (`sys_choice_*`) for state, request type, and what-needed fields.
- `checksum.txt` — ServiceNow-generated checksum over the export.
- `sn_source_control.properties` — app path within the repo (root).

To find a record by name, grep the `<name>` or `<sys_name>` field, e.g. `grep -l '<name>NeedItUtils</name>' update/*.xml`.

## Editing rules (from README)

- Files are **generated by ServiceNow** and validated against `checksum.txt`. Hand-editing files under `update/`, `dictionary/`, `author_elective_update/`, or the `sys_app` file can make the repo un-importable into an instance. If an edit outside the instance is required, flag this to the user; recovery is to `git revert` the non-instance commits or `git reset` to a known-good instance-generated commit.
- Avoid merge commits that mix files from different revisions.
- Dependencies (Task table schema, System Import Sets) are not managed by source control and must be activated on the instance before importing.
- Scripts target `helsinki_es5` (ES5 JavaScript — no `let`/`const`, arrow functions, etc.) and use ServiceNow server/client APIs (`GlideRecord`, `g_form`, `gs`, ...).

## CI

`.github/workflows/main.yml` (the only non-ServiceNow file besides README/CLAUDE.md):
- **Quality Clouds Scan** on pull requests / manual dispatch via `qualityclouds/action-full-scan` (needs `QC_TOKEN` secret); PRs fail on blocker issues.
- **Write-off ChatOps**: an OWNER/COLLABORATOR comment `/writeoff ids=1,2 reason=REASON desc="text"` on a PR posts a bulk write-off to the Quality Clouds API. When replying inline to a QC review comment, `ids=` can be omitted and is parsed from the parent comment's `Issue ID: N` line.
